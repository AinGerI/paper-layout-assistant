# 格式回归与证据范围

本轮根因：原 profile 将 Heading 1 设为 left；任务内摘要样式复制 Heading 1，继承 left；旧检查仅核对部分样式属性，漏查标题对齐和段落直接覆盖。因此以明确角色、配置、验收三者对应解决，不给宏加论文格式修补逻辑。

默认角色：论文大标题居中；一级章标题居中；二三级标题左对齐；摘要/参考文献标题居中且不作为章；正文两端对齐、首行两字符；关键词左对齐零缩进；题注居中零缩进；表格按独立配置。

新增 audit_layout.py 遍历主文和单元格段落，按直接格式→样式→基样式读取有效对齐、字符缩进和行距，报告异常左右/悬挂缩进及未知角色。未知/编号缩进需单独核验，不能静默通过。图片段沿用图片检查；页眉页脚、文本框、编号样式链和文档默认层不在此工具的完整解析范围，涉及这些对象须另验。脚本是结构检查，不模拟 Windows 排版。

检查必须在局部后处理之后执行。不可只用同一 profile 自我验证：本轮测试还以固定预期检查一级标题居中和前后文角色，并故意注入左对齐、零缩进覆盖，要求检查失败。正常稿和故障稿都需覆盖。

截图中的正文首行缩进问题尚未确诊；本轮不宣称已复现或修复 Windows 现象。未来取得对应实际 DOCX 后，应对比段落、样式、编号及兼容属性，再决定修改位置。不要先给每段强写格式掩盖原因。

页面检查按角色列清单：大标题、摘要标题、每级章标题、正文首行、题注、表格。仅看裁切/空白页不足以证明对齐和缩进正确。Windows 与无界面渲染有差异时，保留目标端反馈，不以 XML 声明覆盖实际效果。

题注间距漏检已纳入回归：审计所有已识别角色的段前/段后磅值，并检查自动段间距、按行段间距覆盖。故意把题注段后6磅改为30磅、段前改为0、启用自动间距或按行间距，均必须失败。
