# 格式配置与转换

## 默认格式

| 角色 | 默认行为 |
|---|---|
| 文档标题 | 黑体，小二（18 pt），居中，零首行缩进 |
| 正文 | 中文宋体、小四（12 pt），英文 Times New Roman，1.5 倍行距，首行 2 字符 |
| 一级/二级/三级标题 | 独立 Word 标题样式；14/12/12 pt，零首行缩进；一级居中，二/三级左对齐 |
| 图名、表名 | 继承正文的字体字号，居中，段前/后各 6 pt，零首行缩进 |
| 公式代码段 | 独立普通正文级样式，零首行缩进；编译后由宏安排公式和编号 |
| 表格文字 | 默认10.5 pt，单倍行距，零首行缩进；可配置 |
| 参考文献 | 独立角色，去除来源多余前导空格；可配置 |

标题字体字号、正文缩进和行距来自 profiles/chinese-paper.json；这些是该工作流默认值，用户明确模板优先。不要把“所有中文”理解为标题、题注和单元格也首行两字。

首行缩进同时设置 Word 的字符单位 firstLineChars=200 和兼容用的点值；前者明确表达两字符。零缩进角色显式设置 firstLineChars=0，避免继承正文值。中文字体写入 eastAsia，英文写入常规西文字体；不是只设置界面显示的一个字体名。

## 运行

优先使用已有可用 Python 环境直接运行脚本。需要新环境时，把本包复制到当前任务目录，在该任务副本中执行下面命令；不要在已安装的全局 skill 目录内创建环境或修改锁文件：

```sh
uv sync --frozen
uv run python scripts/markdown_to_word.py /absolute/source.md /absolute/result.docx --work-dir /absolute/job/checks --profile profiles/chinese-paper.json
```

输入、输出、检查目录使用明确路径。脚本拒绝覆盖已有输出：修订时选新路径或按用户授权的文件替换流程操作。检查目录放在当前任务中，不写全局缓存式任务状态。图片相对于 Markdown 文件解析。

## 改格式

复制 profile 到当前任务目录后修改，再将该路径传给 --profile；不要为每篇论文改脚本或宏。

- fonts.east_asia / fonts.latin：全局中文和西文字体。
- roles.body：size_pt、line_spacing、first_line_chars、before_pt、after_pt、alignment、bold；角色字体可另行覆盖。
- roles.title / heading_1 / heading_2 / heading_3：文档标题和三级标题分别定义。
- roles.caption：默认省略字体字号，自动采用正文；用户要求另设题注时才覆盖。
- roles.equation / table / references：分别设置对应角色，不影响正文。
- page：纸张宽高和四边页边距，单位厘米。
- figure：最大宽高（厘米）。按图片DPI估算尺寸，只缩小超限图片，不放大到边界；DPI缺失或非法时按96 DPI估计。
- table：三线表、重复表头、是否允许行跨页。
- equations.disable_grid：生成时关闭含公式段落的网格选项；Windows 宏转换后继续保证关闭。
- equations.single_omega_tilde_compat：已知单个 omega 宽波浪号兼容替换，发生时记录。不要推广为所有重音的替换规则。

line_spacing 的 1.5 表示1.5倍，不是固定1.5磅。不要把正文设为很小的固定磅值来压公式：高公式本身仍需要高度，关闭文档网格只是去除额外撑开的部分。

换 profile 后重新生成 Word；这能确定生成阶段的排版。已经在 Word 中完成 MathType 编译的稿子，应局部修改样式，不能用原始 Markdown 重建后声称保留了后续 Word 编辑。


## 继承的完整排版经验

模板取样、样式继承、关键词局部字体、悬挂缩进、复杂表格、图片透明度、参考文献与最终页面检查，按 [继承的排版规则](inherited-layout.md) 执行。当前JSON不支持的高级属性不要当作已经实现；可选原YAML引擎及补充实现见 [原引擎使用边界](legacy-word-format.md)。

## 图片尺寸策略

使用图片有效DPI估计厘米尺寸；没有有效DPI时使用96 DPI，并在coverage.json的pictures列表记录这是估计。横纵DPI不同时取较大值，用统一比例保持像素宽高比，不声称复原非等向DPI的物理比例。

最终尺寸取原估计尺寸、profile上限、页面可用宽高三者约束，只缩小，不为了填满页面自动放大。100×100像素且无DPI的小图现在约2.65×2.65厘米；图像原像素不变。每图记录源路径、块位置、像素、DPI及采用原因、最终厘米尺寸。

错误的DPI元数据可能给出不适合阅读的尺寸；按来源/用户要求核对。明确需要放大某张图时，在任务中按该图局部调整并检查清晰度。正常尺寸调整只写记录，不生成弹窗或长串警告。

## 题注识别与纠偏（必须核对）

自动识别使用图/表数字前缀和邻接关系，不能区分所有自然语言语义。例如“图1显示负荷随时间变化，下面进一步解释其趋势。”紧邻图片时也可能成为PWDCaption；不能只写一句“完整正文不会误判”。

1. 在源Markdown中明确每个图表对应的真正题注，标出相邻正文；读取转换记录coverage.json的captions，与该语义清单逐项核对。
2. 对误判的段落，在待编译Word中精确定位该段，将样式恢复为Normal/正文，清除脚本为题注添加的keep-with-next直接设置；字体/缩进/行距继承本次正文profile。不得因为重复文本而批量改所有同名段；有重复时结合源顺序与图表邻接定位。
3. 对漏判的真实题注精确设置PWD Caption及正确的与图/表保持规则。标题、图片段、表格单元格与其他正文不改。
4. 对生成阶段Word可使用任务内python-docx/局部OOXML补丁；保留公式书签、图片关系和全文文字。记录改了哪一段的角色，比较修改前后文字/公式/图表数量与协议标记，再渲染受影响页。已编译含OLE的用户稿则按原文的局部保真流程处理，不重建全篇。

这是最终交付的必做语义核对，不代表冻结的基础解析器已增加自动语义判断。只有用户授权改写时才可调整正文措辞；纯排版保持原文。

## 独立前后文角色与最终验收

`roles.front_heading`：摘要、参考文献的无编号标题，默认黑体14 pt、居中、零缩进；普通章标题仍使用 Heading 1。`roles.keywords`：关键词段，默认正文字体字号、左对齐、零缩进。摘要正文使用 body；需要不同摘要正文格式时明确增设实现和验收，不声称已有专用配置。

Markdown 中 `## 摘要`、`## 参考文献` 被明确识别为 front_heading；关键词以“关键词：”或“关键词:”开头，可写普通段落，兼容旧稿标题形式。不按其他任意标题文字猜测角色。旧 profile 缺少新增角色时自动补充默认值；已有 heading_1 配置保持原值，不强行覆盖用户模板。

完成转换及全部局部后处理后运行：

```sh
python scripts/audit_layout.py manuscript.docx --profile profile.json
```

退出码非零时处理报告中的格式差异；不能将只验证 styles.xml 等同于验证段落最终格式。详细范围见 [格式回归规则](layout-regression.md)。

段落审计同时检查段前/段后磅值，拒绝未核验的自动/按行段间距覆盖。用户交付物遵循 SKILL.md 的清爽交付规则；内部保留 Markdown 与检查记录不等于默认交付它们。
